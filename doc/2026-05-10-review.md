This review is dated 2026-05-10 — the first new review since the SMP
enablement landing (`fbc230b`) and the ACPICA integration landing
(`7b0094c`). The 2026-05-05 revision-2 review captured the SMP-enabled

the project from the source, focusing on what the next steps toward
[`GOALS.md`](../GOALS.md) actually are.

## 1. Executive summary

### current project state

- The substrate is mature: dual-entry boot through one `BootInfo`
  contract, higher-half kernel + kernel-owned direct map, ACPI-first
  platform discovery (now via ACPICA), per-CPU run queues with
  load-balanced SMP scheduling, dynamic IRQ vector allocation with
  MSI-X / MSI / IOAPIC INTx fallback, request-shaped `virtio-blk`,
  ARP-level `virtio-net`, xHCI + HID boot-keyboard, dynamic `kmem`
  slabs, `WaitQueue`/`Completion` primitives wired through every
  kernel wait, an HPET-calibrated LAPIC scheduler, and a structured
  observe ABI exposed to a ring-3 shell.
- Biggest landed change since the prior review: ACPICA integration.
  The hand-rolled AML interpreter at
  `src/kernel/platform/acpi_aml.cpp` collapsed from ~1500 to 70 lines;
  a new 1874-line OS-services-layer integration at
  `src/kernel/platform/acpica_integration.cpp` plus 576-line OSL glue
  at `src/kernel/platform/acpica_osl.cpp` drive ACPI table discovery,
  namespace load, device enumeration, `_PRT` resolution, and
  `_PS0`/`_PS3` transitions through upstream ACPICA pinned at
  submodule SHA `232ff3f8` (release `20260408`).
- A new `OS1_OBSERVE_ACPI = 11` snapshot (`Os1ObserveAcpiRecord` in
  `src/uapi/os1/observe.h`) and a new `/bin/acpiprobe` user program
  expose `_PRT` / power-management round-trips from userland.
- The page-frame allocator now has the named tier-2 lock
  `g_page_frames_lock` (`src/kernel/core/kernel_state.cpp:7`), taken
  via `IrqSpinGuard` at every allocate/free/reserve site in
  `src/kernel/mm/page_frame.cpp` and once in
  `src/kernel/syscall/observe.cpp:300`. This closes the prior
  review's immediate-next-step #7.
- TLB-shootdown IPI has real call sites in
  `mm/virtual_memory.cpp:33-51` (`maybe_shootdown_user_mappings`,
  `maybe_shootdown_user_slot`). Receivers still reload CR3
  unconditionally; this is no longer plumbing-without-callers.
- The ACPI device table is now `kcalloc`-allocated
  (`platform/init.cpp:75-83`) sized from `acpica_count_device_objects`.
- Userland still boots via `/bin/init` → `exec /bin/sh`. Syscall set
  unchanged: `write, read, exit, yield, getpid, observe, spawn,
  waitpid, exec`.

### strongest parts

- **ACPI substrate is now reference-grade.** Replacing a hand-written
  AML interpreter with ACPICA closes the biggest single risk in
  platform discovery. The integration is properly walled off: ACPICA
  sources are unmodified inside the submodule, all OS glue lives under
  `src/kernel/platform/acpica_*`, and `acpica_integration.hpp` exposes
  a small set of domain-shaped entry points
  (`acpica_initialize_tables`, `acpica_parse_madt/mcfg/hpet`,
  `acpica_load_namespace`, `acpica_resolve_pci_route_details`,
  `acpica_set_device_power_state`) rather than leaking ACPICA types
  upward.
- **SMP discipline survived the merge round.** ACPICA initialization
  runs on the BSP under `KASSERT_ON_BSP()` at `platform/init.cpp:23`,
  sits before APs come up, and uses the existing `kmem` allocator and
  direct map. Locking-tier order in `wait.cpp` (process before thread
  registry) is preserved.
- **Host test discipline is real.** New
  `acpica_integration_tests.cpp` (429 lines), expanded
  `acpi_aml_tests.cpp` (+325) and `acpi_hpet_tests.cpp` (+141) bring
  meaningful coverage to code that is hard to exercise outside QEMU.
  Source-based test registration (commit `78c9c06`) replaced
  global-constructor registration, and Linux host runs were stabilized
  separately (commit `b0e3ef7`).
- **`run.sh` is now a self-describing menu.** The CMake build emits
  `build/generated/target_menu.txt` and `run.sh` reads it to present
  an interactive target picker. Cheap operator ergonomics that lower
  the barrier for newcomers.

### biggest risks / gaps

- **The descriptor/handle decision is still pending and is now the
  oldest unaddressed gate in the project.** Carried forward from
  multiple reviews. SMP enablement did not move it. ACPICA does not
  move it. VFS, sockets, PTYs, shell redirection, file-backed `exec`,
  multiuser identity, and SSH all wait on this same decision.
  `doc/os-api-draft/` contains drafts; nothing in `src/uapi/os1/` has
  committed to a contract yet.
- **The observe ABI keeps growing in surface area without a privilege
  tier.** Adding `OS1_OBSERVE_ACPI` and the per-CPU SMP fields means
  any unprivileged user program now reads kernel state including AML
  power-state probe results, MSI-X routing, DMA records, and per-CPU
  scheduler counters. As soon as multiuser identity lands, this surface
  will need to retroactively split into "world-readable" and
  "privileged" tiers; defining that split before the surface widens
  further is cheaper than retrofitting it later.
- **ACPICA brings significant external code.** `third_party/acpica`
  is now the largest single dependency in the tree. The kernel build
  links a freestanding subset of ACPICA components compiled under the
  same ABI as the rest of the kernel. There is no documented
  size/footprint baseline yet, no ACPICA upgrade test plan beyond "run
  CI", and no statement of which ACPICA features the project uses
  versus which it deliberately ignores. The integration design at
  `doc/2026-05-06-acpica-integration.md` set out the policy
  (released-snapshot pinning, no in-place edits, OS glue in
  `src/kernel/platform/`); the project must now keep that discipline
  on every future ACPICA roll.
- **AP-targeted device IRQ steering is still not in code.** ISA IRQs
  (`platform_route_isa_irq`) and PCI MSI-X allocations still
  effectively land on the BSP. `kernel_main.cpp:602-608` pins the
  PS/2 keyboard IRQ to the BSP. The SMP synchronization contract
  (`doc/2026-04-29-smp-synchronization-contract.md`) and the SMP
  enablement design call this Phase 8 follow-up. Until it lands, the
  load balancer can move user threads but device IRQs stay on the
  BSP, which means a device-bound workload cannot scale past one CPU.
- **TLB shootdown is broadcast-only.** `ipi_send_tlb_shootdown()` has
  no per-CR3 / per-virtual-address argument. The receiver in
  `core/irq_dispatch.cpp:96-98` reloads CR3 unconditionally. This is
  correct under the only present caller (user-slot teardown reloads
  on every CPU); it will not be correct once `mmap`/`munmap`/COW
  arrives. Any planning toward those features must include a
  granularity refinement pass.
- **`doc/ARCHITECTURE.md` is partially stale.** The 2026-05-05
  documentation refresh updated the SMP language (line 26 mentions
  "per-CPU run queues, reschedule / TLB-shootdown IPIs, and
  load-balanced SMP scheduling"; line 284 says APs join the runtime
  through "pre-created idle threads, per-CPU LAPIC timer ticks, and
  reschedule / TLB-shootdown IPIs rather than parking in `cli; hlt`").
  But the ACPI section (lines 1136-1138) still says PCI INTx fallback
  uses "AML `_PRT` routing, but the implemented AML subset is
  intentionally narrow rather than a general-purpose ACPICA-class
  interpreter." That sentence is now wrong: the implementation **is**
  ACPICA. Line 1048 still references `src/kernel/platform/acpi_aml.cpp`
  as a substantive component, but it is now a 70-line shim. Line 1160
  says "broader ACPI coverage beyond the current minimal AML subset
  when new hardware requires it" which understates what landed.
- **`doc/latest-review.md` still points at the 2026-05-05 revision 2.**
  No mention of the ACPICA landing, the new observe kind, the new user
  program, or the new tier-2 page-frames lock.
- Recommendation: hold the descriptor/handle decision firm. Do not let
  the ACPICA win tempt the project into bolting more raw kernel
  features (more observe surface, more AML hooks, more ad-hoc
  per-process state) onto an undefined resource model.

## 2. Current state from code

### boot path and platform assumptions

- The two boot frontends (`src/boot/limine/`, `src/boot/bios/`) still
  normalize firmware state into the versioned `BootInfo` block in
  `src/kernel/handoff/boot_info.hpp`, including the RSDP physical
  address, memory regions (capped), modules (capped), framebuffer
  layout, and bootloader name.
- `kernel_main(BootInfo*, cpu*)` in
  [src/kernel/core/kernel_main.cpp:362](../src/kernel/core/kernel_main.cpp#L362)
  remains the single shared entry. The order of operations is
  unchanged from the prior review except that
  `platform_discover()` (line 488) now begins with
  `acpica_initialize_tables()` (`platform/init.cpp:26`) before any
  other ACPI work.
- The mapping prelude (kernel image at higher-half, bootstrap identity
  window, direct map, framebuffer, modules, RSDP) is unchanged. The
  CR3 install plus direct-map enable plus `kmem_init(page_frames)` are
  followed by `platform_discover` and only then by `pic_init`,
  `ioapic_init`, `lapic_init`, `interrupts.initialize()`,
  `ipi_initialize()`, driver probe, console, scheduler tasks, idle
  threads, the boot-sequence thread, scheduler-timer prep,
  `cpu_boot_others`, BSP timer arm, and `enter_first_thread`.
- Platform assumptions remain x86_64 + ACPI + LAPIC/IOAPIC + PCI ECAM
  + QEMU/q35-friendly. There is no non-ACPI platform path. ACPI is
  required (`platform/init.cpp:50`).
- The legacy BIOS path is preserved by intentionally disabling HPET
  on BIOS boot (`platform/init.cpp:104-108`) — a real-firmware
  workaround for legacy BIOS boards that wedge on HPET MMIO. This is
  the cleanest example so far of "explicit hardware-quirk isolation
  instead of spreading quirks through generic paths" from
  [`GOALS.md:178`](../GOALS.md#L178).

### memory management

- The three-layer memory story (page frames → virtual memory → `kmem`)
  is unchanged in shape. What changed is locking discipline.
- `g_page_frames_lock` (named in
  [src/kernel/core/kernel_state.cpp:7](../src/kernel/core/kernel_state.cpp#L7))
  is now a real `Spinlock` taken via `IrqSpinGuard` at every
  allocate / free / reserve / direct-map-enable site in
  [src/kernel/mm/page_frame.cpp](../src/kernel/mm/page_frame.cpp). The
  `OS1_LOCKED_BY(g_page_frames_lock)` annotation in
  `kernel_state.hpp:22` makes the contract grep-able. This closes the
  prior review's immediate-next-step #7 and the SMP synchronization
  contract's tier-2 entry.
- `kmem_init` is unchanged in shape. The new ACPICA dynamic device
  table at `platform/init.cpp:75` joins process / thread registries,
  ARP cache, device-binding records, PCI BAR claim records, DMA
  allocation records, IRQ route records, and per-process child-exit
  `WaitQueue`s as `kmem` consumers. The next allocator-lifecycle
  growth is still VFS state (inodes, dentries, descriptor tables) and
  packet buffers, neither of which exist yet.
- `mm/dma.cpp`, `mm/user_copy.cpp`, and `mm/user_address.hpp` are
  functionally unchanged.
- TLB shootdown gained two real call sites in
  [src/kernel/mm/virtual_memory.cpp:33-51](../src/kernel/mm/virtual_memory.cpp#L33-L51):
  `maybe_shootdown_user_mappings(root, virtual_address)` triggers an
  IPI when a user-slot virtual address has its mapping torn down, and
  `maybe_shootdown_user_slot(root, slot)` triggers one when the entire
  user PML4 slot is destroyed. Both ignore non-user slots and the
  detached `~0ull` sentinel. The receiver still reloads CR3
  unconditionally — see "interrupts" below.

### interrupts / exceptions

- IDT, fault dispatch, IRQ dispatch are unchanged in shape. New
  things since the prior review are entirely under
  `arch/x86_64/apic/ipi.cpp` and `core/irq_dispatch.cpp`.
- `core/irq_dispatch.cpp:38-130` still drives the per-CPU scheduler
  tick path (`account_scheduler_tick`), the reschedule IPI hook, the
  TLB-shootdown receive hook, BSP-only console-input polling, and
  AP-tick / AP-online event recording.
- `ipi_send_tlb_shootdown()` and its receive-side
  `ipi_handle_tlb_shootdown()` are now wired into a real caller
  (`mm/virtual_memory.cpp` per above). The IPI is still a coarse
  broadcast: every other CPU receives the vector and reloads CR3. No
  per-CR3 mask, no per-virtual-address invlpg, no batching.
- ISA IRQ pinning to the BSP via `platform_route_isa_irq` is
  unchanged. PCI MSI-X allocations still effectively land on the BSP.
- The `T_LTIMER` route remains a `LocalApic`-kind IRQ route published
  by `platform_allocate_local_apic_irq_route` and consumed by
  `core/timer_source.cpp` so AP timer ticks land in the same
  scheduler-tick path as the BSP.

### scheduling / SMP state

- `struct cpu` (`arch/x86_64/cpu/cpu.hpp:51-86`) layout is unchanged
  from the prior review: `current_thread`, `interrupt_frame`, `gdt`,
  `tss`, `idle_thread`, `RunQueue runq`, `timer_ticks`,
  `reschedule_pending`, `irq_stack_thread`, enqueue/dequeue counters,
  `idle_ticks`, `kernel_thread_ping_count`, `migrate_in/out`,
  `balance_idle_ticks`, the linked-list `next`, then `id`/`booted`/
  `magic`, then the embedded kernel stack.
- `src/kernel/sched/scheduler.cpp` (350 lines) implements the
  per-CPU dequeue, the periodic load balancer
  (`scheduler_balance_cpu`, `scheduler_handle_timer_tick`), idle-tick
  accounting, and `record_run_queue_depth`. Constants
  `kBalanceIntervalTicks=64`, `kIdleBalanceTriggerTicks=4`, and
  `kMigrationCooldownTicks=64` are unchanged. The lock-pair
  acquisition order is `cpu_id`-ascending — the explicit deadlock
  guard from the SMP design.
- `src/kernel/proc/thread.cpp` provides the cross-CPU enqueue
  primitive, least-loaded user-thread placement
  (`select_user_target_cpu` via `select_least_loaded_cpu`),
  round-robin kernel-thread placement, the affinity-mask test, and
  per-CPU run-queue lock acquisition. Cross-CPU wake-ups still send
  the reschedule IPI.
- BSP-only annotations remain on `init_tasks`,
  `initialize_thread_table`, `initialize_process_table`,
  `console_input_initialize`, the keyboard handler, and key
  driver-probe paths. The remaining annotations are intentional
  (single-init-only).

### user/kernel separation state

- The syscall set is unchanged: `os1_sys_write`, `read`, `exit`,
  `yield`, `getpid`, `observe`, `spawn`, `waitpid`, `exec`
  (`src/uapi/os1/syscall_numbers.h`).
- `dispatch.cpp` is unchanged in shape — `read` and `waitpid` block
  through `WaitQueue`, every other path is non-blocking.
- The `Process` record (`proc/process.hpp:34-44`) still carries only
  `pid`, `state`, `address_space`, `exit_status`, `parent`, `name`,
  `child_exit_waiters` (`WaitQueue`), and `registry_next`. No
  credentials, no descriptor table, no working directory, no signal
  state, no session, no namespace.
- Thread fields gained `affinity_mask`, `last_migration_tick`,
  `scheduler_cpu`, `run_queue_cpu`, `wait_link` since the SMP round.
  No thread-level priority, signals, or cancellation state.
- `proc/user_program.cpp` still loads images by initrd path only. No
  argv/envp construction. This remains the single most blocking
  small-kernel-change for any non-trivial userland program work.

### storage / filesystem state

- Storage shape is unchanged. `BlockRequest` embeds a `Completion`,
  `block_request_complete()` calls `completion_signal`,
  `block_request_wait()` blocks via
  `block_current_thread_on_block_io` when invoked from a thread
  context.
- `virtio-blk` retains `kVirtioBlkMaxSectorsPerRequest = 8` (4 KiB per
  request) as the bounded multi-sector cap. Sync wrappers chunk by
  `BlockDevice::max_sectors_per_request`.
- No VFS implementation exists yet —
  [src/kernel/vfs/](../src/kernel/vfs/) is still a single README. No
  persistent filesystem above `BlockDevice`. `src/kernel/fs/` remains
  initrd-only.
- No filesystem-backed `exec` path. `exec` is initrd-by-path.
- Recommendation: same as prior review — descriptor model first, then
  VFS skeleton, then a read-only block-backed filesystem smoke (open,
  read, exec).

### drivers / device model

- The device model under `src/kernel/drivers/bus/` and the platform
  layer under `src/kernel/platform/` are unchanged in shape.
- The largest driver-adjacent change is the ACPICA integration:
  - `acpica_initialize_tables` allocates a `ACPI_TABLE_DESC` array on
    the early-boot direct map, registers ACPICA with the boot RSDP,
    and walks tables.
  - `acpica_load_namespace` runs the AML interpreter on DSDT + SSDTs.
  - `acpica_count_device_objects` and
    `acpica_build_device_info_with_capacity` walk
    `\_SB_` enumerating ACPI device objects, recording paths, `_HID`,
    `_UID`, `_ADR`, `_BBN`, `_STA`, and power-method presence into
    `AcpiDeviceInfo` records.
  - `acpica_resolve_pci_route_details(bus, slot, function, pin, …)`
    looks up `_PRT` for INTx fallback.
  - `acpica_set_device_power_state(path, AcpiPowerState)` invokes
    `_PS0`/`_PS3` for power-management probe.
- INTx fallback still flows: MSI-X first, then MSI, then IOAPIC INTx.
  The INTx path now resolves through ACPICA `_PRT` rather than the
  hand-rolled AML interpreter; the firmware-populated
  `interrupt_line` is the secondary fallback.
- `device_probe.cpp` still runs on the BSP before APs come up; no
  driver currently runs on an AP. Per-CPU IRQ steering remains
  out-of-scope for this round.
- Recommendation: as before, when descriptors and VFS land, expose
  devices through the same handle path used for files. Do not let
  driver control surfaces fork off another ad-hoc ABI.

### networking state

- Unchanged from the prior review. `virtio-net` runs through the
  shared virtio PCI transport, MSI-X RX/TX completion, and an ARP
  probe smoke (`src/kernel/drivers/net/virtio_net.cpp`,
  `arp_cache.cpp`). No IP, ICMP, UDP, TCP, DHCP, DNS, packet pool,
  socket API, or networking syscall.
- Networking is gated on the descriptor decision and on a packet-
  buffer-pool plan. SSH is gated on TCP, entropy, credentials,
  permissions, PTYs, sessions, and file I/O.

### security / multiuser state

- Unchanged. [src/kernel/security/](../src/kernel/security/) is still
  a README placeholder. No uid/gid, no credentials field on
  `Process`, no permission check anywhere. The observe ABI exposes
  broad kernel state to any user program; the new
  `OS1_OBSERVE_ACPI` snapshot widens the surface further with
  AML-derived `_PRT` and `_PS0`/`_PS3` probe results.

### GUI / terminal state

- Unchanged. The terminal model exposes 12 logical terminals over a
  text backend that can render through VGA text mode or framebuffer
  text. Console output serialization (added in commit `61bbb4f`
  before the prior review) survives. No PTY, no compositor, no
  windowing, no mouse routing past xHCI HID recognition.
  [src/kernel/console/pty/](../src/kernel/console/pty/) is still a
  README.

### build, tooling, and debug workflow

- `run.sh` is now a self-driving menu that reads
  `build/generated/target_menu.txt` (16 entries today including the
  default `run`, the serial variants, and the smoke matrix).
- The host-test set added `acpica_integration_tests.cpp` (429 lines)
  and expanded `acpi_aml_tests.cpp` (+325 lines) and
  `acpi_hpet_tests.cpp` (+141 lines). Existing host stubs in
  `tests/host/support/` picked up the SMP layout fields. The host
  harness now uses source-based test registration
  (commit `78c9c06`) rather than global constructors
  (commit `80db2c7`), which makes Linux host runs more deterministic
  (commit `b0e3ef7` referenced "Linux ACPICA host test runtime
  failures" — this matters because the prior review was written from
  a macOS host).
- The QEMU smoke matrix and the `RUN_SERIAL` plus
  `RESOURCE_LOCK os1_qemu_smoke_artifacts` discipline from the prior
  review survive. The smoke set still covers `smoke`, `smoke_observe`,
  `smoke_balance`, `smoke_spawn`, `smoke_exec`, and the BIOS-side
  variants; `smoke_xhci` is UEFI-only. There is no dedicated ACPICA
  smoke yet — the new `OS1_OBSERVE_ACPI` snapshot is exercised through
  `acpiprobe` but not asserted by smoke as far as the source shows.
- `run.sh` also scrubs environment variables for QEMU (commit
  `60eb2ec`) which makes host-side execution less sensitive to the
  developer's shell environment.
- Serial logs remain the primary low-level debug stream; the kernel
  event ring (256 records, 17 event types) remains the canonical
  structured one.

## 4. Review of progress against goals

This section uses [`GOALS.md`](../GOALS.md) as target-state. Each
entry calls out a completion estimate and the practical blocker.

- Goal: clean boot and kernel baseline. Completion: high. No new gaps.
- Goal: modern x86_64 boot and handoff. Completion: high. No new gaps.
  ACPI is now ACPICA-backed end-to-end.
- Goal: memory management substrate. Completion: medium-high. Page-
  frame lock is now public and named. The next allocator step is
  per-page user-buffer scatter-gather plus user-DMA pinning, both
  blocked behind real demand.
- Goal: interrupts, timers, platform support. Completion: medium-high.
  AP timers, reschedule IPIs, TLB-shootdown IPIs land. AP-targeted
  device IRQs still gated. AML / `_PRT` is now industrial-grade.
- Goal: scheduling and SMP. Completion: medium-high. Per-CPU run
  queues, balanced placement, cross-CPU wakeups, IPI-driven
  preemption, AP idle threads, AP timer ticks. No priority/affinity
  policy yet (intentionally deferred).
- Goal: process model and userland. Completion: medium. SMP placement
  fields landed. Argv/envp, descriptors, cwd, file-backed exec, user
  heap, sessions, process groups, credentials, signals all still
  missing. This is the goal that has moved least in the last two
  reviews and that gates the most other goals.
- Goal: storage and filesystem. Completion: block medium-high; FS
  zero. Block I/O is request-shaped and uses `Completion`. No VFS, no
  persistent FS.
- Goal: device model and buses. Completion: medium-high. ACPICA
  closes the AML side. Per-CPU IRQ steering and PCIe hotplug remain
  follow-ons. USB hub class, mouse routing past recognition, USB mass
  storage, NVMe, AHCI all still missing.
- Goal: networking. Completion: low. ARP-probe-only `virtio-net`. No
  IP layer or above.
- Goal: security and multiuser. Completion: very low. Same as prior
  review. The widening observe surface raises the cost of getting
  this wrong.
- Goal: GUI and terminal. Completion: terminal medium; GUI zero. No
  PTY, no compositor.
- Goal: build, debug, test. Completion: high. Source-based host-test
  registration, ACPICA host tests, runtime menu in `run.sh`, scrubbed
  QEMU env, parallel-CTest QEMU lock discipline preserved.
- Goal: portability boundaries. Completion: partial. ACPICA is x86-
  centric in current usage but is itself architecture-neutral; no new
  x86-specific assumption was added.
- Goal: accelerator awareness. Completion: not started. Same as
  prior review.

### blockers, missing prerequisites, sequencing issues

- The descriptor/handle/object decision is the oldest unaddressed
  gate in the project and it gates VFS, sockets, PTYs, file-backed
  exec, multiuser identity, SSH, packet pools, and device handle
  shape simultaneously.
- Argv/envp construction in `proc/user_program.cpp` is still the
  next small kernel-side change before any non-trivial userland
  program can be written without baking into the loader.
- Networking is gated on a packet-buffer pool plan and a monotonic-
  time syscall — both still missing.
- SSH is gated on TCP + entropy + credentials + permissions + PTYs +
  sessions + file I/O.
- AP-targeted device IRQ steering needs: a per-vector affinity hook
  in `platform/pci_msi.cpp` and a corresponding IOAPIC redirection-
  mask override in `arch/x86_64/apic/ioapic.cpp`. The SMP design
  specifies the shape; the call sites are still not present.
- TLB shootdown granularity beyond "reload CR3 everywhere" is needed
  before any user-side `mmap`/`munmap`/COW work.
- Real-hardware bring-up (visible on the unmerged `real-device`
  branch with ASUS G74SX investigation work) will eventually pull
  hardware-quirk pressure into mainline ACPI/USB/PCI paths. The
  ACPICA win helps here; the next pressure point will be USB hub
  class, AHCI, and BIOS-side firmware variation.

## 5. Overlooked goals / blind spots

These extend the prior review's blind-spots list rather than replace
it.

- **ACPICA upgrade and footprint policy.** Now that ACPICA is the
  ACPI implementation, the project needs an explicit upgrade rhythm:
  release cadence (released-snapshot only, no floating master), a
  per-roll review checklist (size delta, host-test pass, QEMU smoke
  pass, BIOS smoke pass), and a documented baseline footprint
  (kernel-text bytes, kernel-data bytes, kmem-pressure delta). The
  integration doc names the rules; the project should turn them into
  a checklist before the first ACPICA bump.
- **Observe access tier policy is now overdue.** The observe ABI now
  exposes per-CPU SMP counters and ACPI namespace device records
  including AML power-state probe results. As soon as multiuser
  identity arrives, the surface will need a privileged/unprivileged
  split; deciding it now keeps each new observe-kind from making the
  retrofit harder.
- **A per-page TLB-shootdown shape decision.** Today shootdown is a
  broadcast CR3 reload. Before any `mmap`/`munmap`/COW lands, the
  project needs to decide between (a) per-CR3 set + invlpg list,
  (b) per-vCPU lazy IPI batching, or (c) generation-counter style
  invalidation. The decision shapes how `VirtualMemory::unmap` and
  `protect` are written.
- **A documented AP-IRQ steering policy.** Same as prior review,
  unmoved.
- **An error ABI.** Same as prior review. `os1_status` or an
  errno-compatible numbering should land before VFS so descriptor
  APIs do not introduce a third return-code style on top of "negative
  on error" + bool-out-pointer.
- **An entropy source.** Same as prior review. Per-CPU tick deltas
  plus interrupt timing remain the cheapest first option. Define the
  policy before designing it.
- **A static or runtime lock-order assertion.** Same as prior review.
  Phase 5 of any future SMP expansion (priority, threaded IRQs)
  becomes much riskier without one.
- **A `BootInfo` capacity-cap document.** Same as prior review. The
  current caps for memory regions, modules, and CPUs live as
  constants; they should be part of a documented stable handoff
  contract.
- **An ACPI / device-namespace observability split.** The new
  `OS1_OBSERVE_ACPI` snapshot reports counts and a single resolved
  route. A future review-able shape (per-device records, like
  `OS1_OBSERVE_DEVICES` is for the bus model) would let the shell
  show the ACPI namespace the same way it shows PCI, which would in
  turn help the real-hardware bring-up that the `real-device` branch
  has begun.
- **A monotonic-time syscall.** Same as prior review. Required by any
  network protocol work and any timeout primitive in user space.
- **A packet-buffer-pool design.** Same as prior review. Extending
  `virtio-net` past ARP requires it.
- **A documented "what ACPICA is allowed to do" boundary.** ACPICA
  has hooks for sleep states, GPE handling, embedded-controller, and
  power-button events; the project does not need or want all of
  them. A short doc that says which ACPICA features the OSL stub
  intentionally leaves disabled would be cheap and would make future
  CVE / advisory triage tractable.

### explicit ordering constraints

- Before networking: finish descriptor semantics or keep networking
  entirely kernel-internal. Same as prior review.
- Before networking: add packet-buffer ownership and a monotonic-
  timeout primitive.
- Before SSH: finish TCP, entropy, credentials, permissions, PTYs,
  sessions, file I/O.
- Before GUI: finish PTYs, sessions, input event routing, framebuffer
  ownership.
- Before further SMP scheduling work (priorities, threaded IRQs):
  finish AP-targeted device IRQ steering, document AP-IRQ policy,
  add a static or runtime lock-order assertion.
- Before POSIX growth: decide which POSIX ideas are compatibility
  requirements and which native APIs are intentionally different.
- Before accelerator support: define DMA pinning, device permissions,
  reset policy, no-IOMMU risk model.
- Before writable filesystems: define cache, sync, crash, corruption
  behavior.
- Before real-hardware claims: test at least one non-QEMU machine
  class and record which firmware/device assumptions failed. The
  `real-device` branch has begun this.
- Before any future `mmap`/`munmap`/COW or page-out: refine TLB
  shootdown beyond CR3 broadcast.
- Before accepting new ACPICA features into the OSL stub: document
  why each is needed and what privilege boundary it sits behind.

## 7. Immediate next steps

The list below is prioritized by what unlocks the most downstream
value relative to cost. Items 1-5 carry forward unchanged from the
prior review because the substrate landings did not move them. Items
6-10 are sharpened or new because of what just landed.

1. **Decide and document the minimal descriptor/handle contract.**
   Still gates VFS, devices, sockets, PTYs, shell redirection, and
   SSH. The SMP scheduler now means user processes may sleep on
   cross-CPU wakeups; the descriptor table will compose with that
   wait-queue path. Defining the contract now keeps descriptor
   lifetime and wait-queue lifetime aligned.
2. **Implement a per-process descriptor table.** Route console fd
   0/1/2 through it. Tests the contract before filesystem complexity.
3. **Add argv/envp stack construction for `spawn`/`exec`.** Touches
   only `proc/user_program.cpp`, the user-side `_start`, and one
   syscall ABI line. Required before any non-trivial user program.
4. **Add a minimal VFS with initrd as the first mounted backend.**
   Converts initrd-specific program loading into a general path-
   lookup mechanism. Sets the shape for the first persistent FS.
5. **Move `exec` to VFS lookup while preserving initrd boot.**
   Prevents a second program-loading path from fossilizing.
6. **Refresh `doc/ARCHITECTURE.md` ACPI section and
   `doc/latest-review.md`.** ARCHITECTURE.md still describes the AML
   interpreter as a hand-rolled minimal subset (lines 1048,
   1136-1138, 1160); the integration is now ACPICA. The
   `latest-review.md` pointer must move to this review.
7. **Define an observe-access tier policy.** The observe ABI grows
   with every new subsystem; `OS1_OBSERVE_ACPI` widens it further.
   Settle the privileged-vs-unprivileged split before multiuser
   identity arrives.
8. **Pick and document the AP-targeted device IRQ steering policy.**
   Required before any device driver author makes the choice
   implicitly. ACPICA `_PRT` resolution unblocks the prerequisite
   data-shape question; the steering decision is now strictly about
   MSI affinity, IOAPIC redirection mask, and lowest-priority
   logical routing.
9. **Add a debug-build lock-order check.** Per-thread highest-tier-
   held counter, asserted in `Spinlock::lock`. The SMP contract is
   now load-bearing for correctness; the next inversion will not be a
   single-file fix.
10. **Choose and implement the first block-backed filesystem and the
    deterministic image tool.** The block path is mature; the
    missing value is persistent namespace semantics, not more block
    smoke. Pair with a read-only mount smoke and (after descriptors
    land) a filesystem-backed `exec` smoke.

Lower-priority but still in the immediate window:

11. **Add minimal credentials to `Process`.** Tie the first
    permission check to the new VFS path so credentials and
    namespace land together.
12. **Add a monotonic time syscall and kernel timeout primitive.**
    Required by network protocol work and eventual SSH timeouts.
13. **Define a packet buffer pool.** Required before extending
    `virtio-net` beyond ARP; design before TCP planning starts.
14. **Document the ACPICA upgrade checklist and the OSL feature
    boundary.** Cheap; pays off the first time an upstream advisory
    pressures the project to roll the submodule.
15. **Refine TLB shootdown granularity.** Per-CR3 + per-virtual-
    address invlpg list. Should land before any user-facing
    `mmap`/`munmap`/`mprotect` syscall.
16. **Document the `BootInfo` capacity caps as part of the boot
    ABI.** Carry-forward.
